3. Remove orphaned prototype code P3 Shipped

A reachability pass from the live routes (/ → hero + HomePublicContent; /dashboard → DashboardV4) shows a whole prototype chain that nothing renders any more: an A/B design switcher, an interactive home/dashboard switcher, two dashboard prototypes and several dead compare/home pieces. Delete only the never-referenced design/* + switcher chain; leave the dashboard prototypes (DashboardV2/V3) in place for now.

3.3 Choice DEAD-2 — HomeLayoutV4 (surgical)

Move NewsListConcept + CampaignsColumnConcept (+ HomeLayoutV4Props) into a small components/home/concept/ module; delete the dead full HomeLayoutV4 layout and FeaturedTherapeuticBand.

Keep HomeLayoutV4.tsx as-is (dead full layout retained). Lowest churn, but the dead code stays.

4. Lightbox accessibility P2 Shipped

The product-detail video lightbox (components/ProductVideosSection.tsx) opens a full-screen overlay with a hand-rolled Escape handler and body scroll-lock, but it does not trap focus, does not restore focus to the trigger on close, renders inline (not via a portal) and has no accessible name on the dialog or the <iframe>. The Round 2 Modal already solves every one of these.

4.1 Current gaps

ConcernTodayVia Modal
Focus trapNoneBuilt-in
Focus restore on closeNonerestoreFocus
Portal + scrimInline overlayPortal
Escape + scroll-lockBespoke effectBuilt-in
Accessible nameMissingariaLabel + iframe title

4.2 Choice LIGHT-1 — approach

Option A — refactor onto <Modal variant="center"> (recommended)

Use scrimClassName="bg-black/75", a transparent panelClassName, initialFocusRef on the close button and restoreFocus="previous"; delete the manual Escape/scroll-lock effect. Inherits the trap + portal for free.

Option B — patch the bespoke overlay

Keep the custom overlay but add trap / restore / portal by importing the same hooks (useFocusTrap, useLockBodyScroll). More code, diverges from the primitive.

4.3 Choice LIGHT-2 — accessible name

Option A — dynamic ariaLabel + iframe title (recommended)

Set the dialog ariaLabel and the <iframe title> to the selected video’s title. No visible chrome change.

Option B — visible heading + aria-labelledby

Add a visible title bar above the player and label the dialog from it. More visual change to the lightbox.

5. Consent-gated analytics P2 Shipped

Today HotjarWhenConsented in components/CookieConsentRoot.tsx loads Hotjar unless the user has explicitly rejected — so analytics runs for visitors who have not yet answered the banner. That is an opt-out posture, while the /cookies copy and the consent pattern describe opt-in. This section reconciles policy and copy.

5.1 Current flow

consent state 'unset' (banner unanswered) → Hotjar loads
state 'analytics' (accepted) → Hotjar loads
state 'essential' (rejected) → Hotjar blocked

The gap is the first row: a visitor who has not chosen yet is already being tracked.

5.2 Choice CONSENT-1 — policy

Option A — strict opt-in (recommended)

Load Hotjar only when state === 'analytics' — a one-line change in CookieConsentRoot. Unanswered → no analytics, matching the copy and GDPR/PECR opt-in.

Option B — keep opt-out, fix docs only

Leave the load-unless-rejected behaviour and instead rewrite the /cookies copy + consent pattern to describe opt-out honestly.

5.3 Choice CONSENT-2 — align copy & naming (proposed)

Reconcile the HotjarWhenConsented JSDoc, the /cookies page copy and patterns/consent.html with whichever policy CONSENT-1 picks, so all three agree.

5.4 Choice CONSENT-3 — post-choice confirmation strip

Option A — add the strip

Add the “You’ve accepted/rejected analytics — change” confirmation strip from the DS consent pattern.

Option B — defer (recommended)

Keep Round 4 tight; the strip is a nicety, not a compliance fix. Revisit later.

Source: Consent & cookies pattern; components/CookieConsentRoot.tsx, app/cookies/.

Two small consistency items. Icons come from three sources — lucide-react (the de-facto set, 31 files), a handful of <wa-icon> web-awesome custom elements, and the bespoke HealthIcons condition glyphs. Disabled state mixes native disabled, aria-disabled and a drift of opacity-40/45/50 values.

6.2 Choice ICON-1 — target set

Option A — lucide as the single UI set (recommended)

Migrate the 5 wa-icon usages (SaveToggleButton, CompareToggleButton, ExpressInterestWhiteButton, SharePagePanel) to lucide (Bookmark/Share2/Mail/GitCompare), handle the saved state via lucide fill, and drop the @awesome.me/webawesome dep + webawesome-elements.d.ts.

Option B — keep web-awesome for the bookmark fill

Migrate everything except the saved-bookmark fill toggle, which stays on web-awesome. Keeps the extra dependency.
