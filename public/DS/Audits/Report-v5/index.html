A fresh, full UX audit of the HealthStore product, taken with new eyes after Rounds 2–4 shipped the primitives from the v1 audit. Where v1 focused on component reuse, this pass focuses on experience: feedback, states, forms, content, navigation, responsiveness and density — plus where documentation has drifted from the code. Cookie consent is intentionally out of scope.

1. Executive summary

The component layer is in noticeably better shape than at v1. The shared primitives are real and well-built: components/ui/Button.tsx (six variants, proper toggle/loading/aria-disabled handling) and components/ui/Modal.tsx (portal, focus trap, scroll lock, escape, focus restore, center/drawer) are genuinely good, and the AI drawer now runs on the shared modal with a real focus trap.

The remaining problems have shifted from “duplication” to experience and follow-through: there is no global feedback layer, so transient actions can fail silently; several surfaces conflate “empty” with “error”; the new FormField is only partially adopted; the PDP is dense with competing actions; and a few routes are orphaned from the navigation. A cross-cutting concern is documentation drift — some round records claim migrations the code hasn't actually had yet.

2. What changed since v1

For full detail see the round records (R2, R3, R4). In short:

  • Shipped Button + Modal primitives; 12 buttons and 4 overlays migrated; AI drawer gained a focus trap.
  • Shipped Radius scale via Tailwind @theme; #005EB8 → var(--nhs-blue) token sweep.
  • Shipped FormField, AuthCard, WidgetShell; badge/pill + collapsible consolidation; orphan prototype layouts removed.
  • Shipped Product-video lightbox a11y (trap + label) and icon set standardised on lucide.

This audit takes that as the baseline and looks for what's left and what's newly visible.

6. Documentation vs code drift

A meta-finding worth fixing because it undermines trust in the design system:

Claim (in DS / round records)Code reality
R3: login / select-entity / EOI / org-settings / catalogue filters migrated to FormField.R6 Org-settings now on FormField + Button; select-entity radios given a labelled role="radiogroup". Catalogue filters still only use the shared Select (the rest is raw HTML). Login & EOI already did.
Compare matrix “kept” (CMP-001); CompareViewToggle built.CompareMatrixView + CompareViewToggle exist but aren't wired — shipped UI is workspace-only; the matrix is a dead path.
Cookie consent “docs aligned to say so honestly”.Out of scope for this audit — not re-verified.

Do

  • Mark a migration “done” only when every listed surface is on the primitive.
  • Remove or wire dead components (matrix, view toggle).

Don't

  • Let round records assert completion ahead of the code.
  • Keep built-but-unused UI without a flag/route.
