Component audit & reuse report

A retrospective UX and component audit of the HealthStore product. It catalogues every component, identifies where the same problem is solved in multiple ways, and proposes a tightened, reusable component set with a prioritised plan to get there.

Scope
~70 components, ~32 pages
Tech
Next.js 16, React 19, Tailwind v4
Token layer
app/globals.css (solid)
Version
v1 (first pass)

1. Executive summary

HealthStore has a strong foundation but a fragmented component layer. The token system in app/globals.css (colour, type scale, shadows) is well-considered, and several components are genuinely well-built and accessible — notably PdpTabs, the three portal modals, the badge system, and the compare controls.

The main weakness is duplication of common primitives. There is no shared button, card surface, modal, or form field component, so the same patterns are re-implemented inline across dozens of files, often with hardcoded hex values and inconsistent radii. There is also a meaningful amount of prototype / orphaned code (alternate home and dashboard layouts, an unused design-switcher) that inflates the surface area.

4. Accessibility findings

Strengths

  • Skip link + #main-content landmark in AppShell.
  • PdpTabs: full role="tablist" semantics with arrow-key roving focus.
  • Portal modals (EOI, Clear data, Share): escape, focus trap, focus restore, labelled titles.
  • CompareLensControl fieldset/legend; CompareViewToggle aria-pressed; compare row-count aria-live.
  • Global :focus-visible yellow outline; reduced-motion and print stylesheets.

Delivered — see the Round 4 record for the decisions applied.
