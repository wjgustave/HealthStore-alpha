R2-2 — Projected-impact denominator & framing

The “What this could mean for {area}” section multiplies a published effect size by a local population. Which population, and point estimate or range? This is the biggest credibility lever on the page.

Why this matters. The ported code (Option A) applies the effect % to eligible × 75%. For West Yorkshire that is 66,750 × 40% = ~26,700 “fewer admissions” — larger than the 4,200 admissions the ICB actually has. That is not defensible. B/C/D fix the denominator.

Option A — eligible × 75% uptake (current code)

Point estimate on the whole eligible cohort. Overstates — see note above. Keep only if reframed as “reach”, not “admissions avoided”.

Option B — high-risk monitored cohort

Apply effect to the ~17,800 high-risk cohort at a realistic monitored fraction. Defensible for remote monitoring; single number.

Option C — conservative→evidence-led range

Show a band (30–48% admission effect) on the chosen denominator. Honest about uncertainty; a range is harder to headline.

Option D — high-risk cohort × range rec Chosen

Defensible denominator and a range, with the uptake assumption shown. Best evidence hygiene.

Visual — Option A (as-ported) vs Option D (recommended), West Yorkshire

Option A — overstated

Exceeds actual activity — not defensible.

Option D — high-risk cohort × range

So what? Monitoring ~8,900 high-risk patients (50% of the high-risk cohort) could avoid roughly 1,070–1,710 admissions a year, against 4,200 today.

R2-3 — ROI cohort wiring

The ROI engine currently hard-codes a 500-patient monitored cohort. What should drive it once the area is known?

Option A — derive from coverage funnel rec

e.g. 10% of eligible (capped), so numbers scale with the area. West Yorkshire → ~8,900.

Option B — actual local live users

Use the real deployment (active_users = 612 for Luscii in West Yorkshire). Truthful, but small and reads as “today” not “potential”.

Option C — user-adjustable input

A slider/number the commissioner sets, defaulting to the local-derived value. Most flexible; more UI.

Option D — labelled illustrative default Chosen

Keep 500 but label it clearly and allow override. Lowest change; least local. Chosen for now — revisit to funnel-derived (A).
