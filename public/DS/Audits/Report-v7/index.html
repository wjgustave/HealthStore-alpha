Round 7 — clarity & density

Round 6 made the product say what happened and tell errors from empty. Round 7 turned to clarity & density and shipped: a calmer PDP with one clear primary action, navigation that highlights the right item on every /apps route, one consistent “DTx app” vocabulary, a compare experience without dead paths or invisible empty states, and the last destructive one-clicks made safe. Two items were deliberately held back per the decision log: the repeated Express-interest CTA was left as-is (PDP-4), and surfacing the orphaned workspace routes in the nav (NAV-1) was deferred to a future iteration. Vocabulary standardised on “DTx app” (an override of the recommended plain “app”).

3. PDP triage P2 Shipped

The PDP hero (app/apps/[slug]/page.tsx) currently carries five controls — an Express interest primary, a Demo available link, then a Share / Save / Compare toolbar — and repeats Express interest again in a bottom callout. Above the H1, up to seven badge / pill types can wrap (condition tags, supervision model, maturity, NICE refs, content confidence, plus NHS App + Demo below). The result reads as competing CTAs and badge noise (RSP-01).

3.1 The hero today (live mock)

COPD Self-management Pilot NICE EVA Supplier-reported ✓ NHS App
myCOPD
A guided self-management app for people living with COPD.

Six pills above the title; four actions of similar weight; “Express interest” also repeats lower down the page.

3.2 Choice PDP-1 — action hierarchy

Option A — one primary, the rest a quiet utility cluster (recommended)

Keep Express interest as the only filled primary. Group Save / Compare / Share into a single right-aligned secondary cluster (smaller, consistent icon + label) so the decision is unambiguous.

Option B — keep four actions, re-rank by weight only

Leave all four in the hero but make only EOI a filled primary and the rest ghost/borderless. Smaller change; still three competing utilities beside the CTA.

3.3 Choice PDP-2 — demoted-action treatment

Option A — compact icon + label cluster (recommended)

Keeps labels (clearer for commissioners), just smaller and visually subordinate.

Option B — icon-only buttons (with aria-label)

Densest, but relies on icon recognition; less obvious to a non-technical audience.

3.4 Choice PDP-3 — hero badge trim

Option A — keep signal badges, move the rest below (recommended)

Hero keeps condition tags + at most one or two decision signals (maturity if not “Established”; content confidence). Supervision, NICE refs and the NHS App badge move into the commissioning snapshot just below, where governance already lives.

Option B — cap visible pills with “+N more”

Keep all badge types but show the first ~3 and collapse the remainder behind a “+N more” disclosure. Less re-architecture, but adds an interaction and still mixes signal types.

3.5 Choice PDP-4 — the repeated Express-interest CTA

Option A — keep both, differentiate them (recommended)

Hero CTA stays the primary; the bottom callout stays as the “contact the supplier” reinforcement at the end of a long page, with copy that makes its role distinct (not a duplicate button).

Option B — one CTA only

Drop the hero EOI button (or the bottom callout) so the page has a single Express-interest entry point. Cleaner, but loses the end-of-page prompt after a long read.

Shipped (3.5 = do not change): both Express-interest entry points were kept as-is. The hero remains the filled primary; the accent callout below the tabs still reinforces “contact the supplier” at the end of a long page.

4. Fix nav active states P2 Shipped NAV-1 deferred

The logged-in nav has two bars; the workspace bar holds Dashboard, Find apps, Comparison tool, Funding directory. Saved apps and EOI record are reachable only from dashboard tiles / widgets — there is no nav path back (NAV-01). Active state uses strict === equality, so Find apps does not highlight on a PDP (/apps/[slug]) or on /saved-apps (NAV-02). Org-settings has no breadcrumb.

4.1 Choice NAV-1 — surfacing the workspace routes

Option A — a “Your workspace” group (recommended)

Workspace ▾ Dashboard Saved apps EOI record

Group the personal/org routes (Dashboard, Saved apps, EOI record) under one labelled cluster or dropdown in the workspace bar.

Option B — flat items in the workspace bar

Dashboard Find apps Saved apps EOI record Comparison tool Funding

Add them as two more top-level items. Simplest, but the workspace bar gets crowded (6 items).

Deferred (4.1 = do not change): surfacing /saved-apps and /eoi-record in the primary nav is held for a future iteration. They remain reachable from the dashboard tiles and widgets. The active-state (4.2) and breadcrumb (4.3) fixes below did ship.

4.2 Choice NAV-2 — active-state matching

Option A — prefix matching with per-route ownership (recommended)

“Find apps” goes active for /apps and /apps/[slug] (PDP) via a startsWith('/apps') check, but not for /saved-apps — which becomes active for its own “Saved apps” item. Each route highlights exactly one nav item.

Option B — add only a saved-apps mapping

Leave Find apps on exact paths; just map /saved-apps to its item. PDP still shows no active nav item.

4.3 Choice NAV-3 — breadcrumb fixes

Option A — add the missing crumbs (recommended)

Add a breadcrumb to org-settings and align the EOI record crumb with the new workspace grouping, so every signed-in page has a consistent trail.

Option B — defer breadcrumb work

Only do the nav grouping + active state now; leave breadcrumbs for a later polish round.

5. Vocabulary pass + Compare toggle label P2 Shipped

The same entity is called different things across surfaces (CNT-01): nav and catalogue say app(s); the PDP section copy and share labels say product; compare mixes application(s) and app(s); saved-apps mixes Products and apps; the AI / funding flows use digital therapeutic / DTx app. And the Compare toggle reads “Compare” in both states (only the icon changes) so it’s unclear whether it adds or removes (CNT-02).

5.2 Choice VOC-1 — the canonical UI term

Option A — standardise on “app” (recommended)

Use app(s) as the single UI noun (it already dominates nav, catalogue, dashboard). Reserve “product” for supplier-facing / share-metadata contexts only. Friendliest for a non-technical commissioner audience.

Option B — standardise on “product”

Use product everywhere (matches procurement language). More formal, but means re-labelling nav / catalogue / save / compare affordances that currently say “app”.

Shipped (override): the canonical noun is “DTx app” (not plain “app”). Per VOC-2 (A), the pass updated the high-traffic body copy & counts on the PDP, comparison tool, and saved-apps surfaces, and removed “application”. Short navigation / breadcrumb / page-title labels (“Find apps”, “Saved apps”, “Comparison tool”) were intentionally left as concise affordances and can be extended later. The AI / funding flows already say “DTx app”, so they now match.

5.3 Choice VOC-2 — scope of the pass

Option A — high-traffic surfaces now; keep DTx as a programme term (recommended)

Normalise PDP / compare / saved-apps copy to the canonical term and drop “application”. Leave digital therapeutic / DTx in the AI & funding flows as a deliberate, narrower programme term (not a synonym for “app”).

Option B — full sweep incl. AI / funding

Also replace DTx / digital therapeutic in the AI advisor and funding wizard. Most uniform, but loses a useful distinction and touches more copy.

Verb tells you what the click does; pressed state reads as “Added”.

6. Compare: kill the dead path, fix empty & overflow P2 Shipped

The shipped compare UI is workspace-only. CompareMatrixView, CompareViewToggle and CompareDecisionSnapshot exist but are never imported — a dead path the v2 audit flagged (and a docs-vs-code drift). Separately, the “Differences only” filter hides every group when nothing differs, leaving an apparently blank workspace with only an sr-only count (UX-04); and the summary / row grids use repeat(n, minmax(140px, 1fr)) with no overflow wrapper, so 3–4 apps can overflow before the 639px stack breakpoint (RSP-03).

6.1 Choice CMP-1 — the dead matrix / view toggle

Option A — remove the dead code (recommended)

Delete CompareMatrixView, CompareViewToggle, CompareDecisionSnapshot and the unused view IDs in compareConfig.ts. The decision workspace is the shipped experience; removing the dead path reconciles docs with code.

Option B — wire the view toggle

Surface the Matrix / Workspace toggle (it already supports ?view= + localStorage) so users can switch layouts. More UI to support and test; reintroduces a second layout to maintain.

6.2 Choice CMP-2 — the “Differences only” empty state (UX-04)

Today — blank body

(nothing visible — only an sr-only “0 dimensions”)

Option A — visible empty state + “Show all rows” (recommended)

These apps are identical on every comparison dimension.

Explains the blank and unchecks the filter in one click.

Option B — auto-disable the filter + note

No differences found — showing all rows.

Filter turns itself off; less user control, but never blank.

6.3 Choice CMP-3 — summary / row overflow (RSP-03)

Option A — horizontal scroll wrapper (recommended)

Wrap the summary + workspace row grids in an overflow-x: auto scroller with a sensible min column width — the same pattern the (dead) matrix already used. Columns stay readable; the panel scrolls instead of overflowing the page.

Option B — responsive column count

Reduce the min column width and/or stack earlier so 3–4 apps fit without scrolling. No scroll affordance, but tighter columns at desktop widths.

7. Density & safety: overflow + destructive confirmations P2 Shipped

Three last issues from the audit. The PDP snapshot strip base row is flex-wrap: nowrap, so pills can overflow on narrow viewports (RSP-02). The saved-apps remove (X) is unguarded — rapid clicks can fire duplicate DELETEs (UX-07) — while the compare “Clear all” wipes the basket on a single click with no confirmation (UX-08). (The Clear-data modal is already a safe two-step; it just needs its confirm button disabled while the request is in flight.)

7.1 Choice SNP-1 — snapshot strip overflow (RSP-02)

Option A — let the row wrap (recommended)

Change .hs-snapshot-strip__row to flex-wrap: wrap (matching the funding variant) with min-widths so pills reflow onto a second line. Simplest, no scroll affordance.

Option B — horizontal scroll

Keep one line but wrap in overflow-x: auto. Preserves a single-row scan; adds a scrollbar on narrow screens.

7.2 Choice DES-1 — saved-apps remove guard (UX-07)

Option A — disable while in flight (recommended)

Read togglingId from BookmarkProvider and disable that row’s X (with a wait cursor) while its DELETE runs — the same guard SaveToggleButton already uses. Also disable the Clear-data confirm button while pending. No duplicate requests.

Option B — optimistic remove

Remove the row from the list immediately on click so a second click can’t hit the same item. Snappier, but rollback-on-error is more complex.

7.3 Choice DES-2 — compare “Clear all” confirmation (UX-08)

Option A — inline two-step (recommended)

→

First click arms; second confirms. No modal, reverts after a few seconds.

Option B — confirm modal

Open the shared Modal to confirm before wiping. Heavier, but consistent with Clear-data.

Option C — clear + undo toast

Clear immediately but show an Undo toast for a few seconds (reuses the R6 toast service). Fastest path; relies on the user catching the toast.
