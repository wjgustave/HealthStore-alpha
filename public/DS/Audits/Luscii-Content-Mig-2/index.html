2. What shipped this round

  • Narrative spine — components/product/PdpNarrativeSpine.tsx: a server component rendering The problem this addresses, How Luscii helps (with the current→proposed pathway visual), and How to buy locally. Each section registers with the existing selective share/print system via PdpSection/PdpShareRegion.
  • Hybrid mount — app/apps/[slug]/page.tsx: the spine renders between the commissioning snapshot and the six reference tabs, so the page reads problem → how it helps → deep detail (tabs) → how to buy. The tabs (Overview, Evidence, Deployment, Safety, Commercial, Technical) are untouched — no data loss.
  • Hero proposition — the hero now leads with the commissioner-framed one-liner for Luscii.
  • Provenance footer — the previously-hidden source_summary / confidence_note / last_reviewed_date now render at the foot of the page.
  • Route retired — /products/[slug] and /products/[slug]/support now permanentRedirect to /apps/[slug]. ProductNarrativeView and the personalisation libraries stay in the tree, dormant, for Rounds 2–3.
Scope guard. The spine and provenance footer are gated to slug === 'luscii' this round (decision SP-3). The other curated narratives (myCOPD, myHeart, Joint Academy) exist but keep the reference-only layout until their own migration records — their content conflicts have not been verified.

3. Content conflicts resolved Applied

The three Section F conflicts were credibility risks, not cosmetics. The steer was to apply the audit’s recommendations now, and to not publish an unverified price.

3.1 CNF-1 — Value proposition

Option A — commissioner-framed Chosen

“A 24/7 remote monitoring service for high-risk COPD patients — patients report symptoms in the app, a clinical hub intervenes before an emergency.” Now the hero headline.

Option B — supplier-framed

“Remote monitoring platform with 25 million global registrations…” Retained in luscii.json but no longer the headline.

3.2 CNF-2 — Device class

Option A — Class IIa SaMD Chosen

The more current value from luscii.json. The narrative’s regulatory_position.device_class and the assurance-domain summary were corrected to match.

Option B — “Class I transitional (HIRA-evidenced)”

The narrative’s prior value. Superseded — it contradicted the catalogue record.

Residual flag. The confidence_note still caveats the classification (“confirm COPD-specific CE certificate with Luscii”). This is deliberate and honest — it stays until supplier confirmation.

3.3 CNF-3 — Price

Option A — publish no figure yet Chosen

Both figures (“From £110/patient/year” and “£30–£60 pppm”) replaced with “Pricing on application — contact supplier (figures pending verification)”. The £110/yr vs £360–720/yr gap was too material to ship.

Option B — pick one figure as canonical

Deferred until the supplier verifies. Investment/grant figures (e.g. £400k NHSE) are context, not price, and were left in place.

4. Page decisions Applied

4.1 SP-1 — hidden facts (showPdpFactsGrid)

Option A — provenance footer Chosen

Relocate sources/confidence into a slim footer; supplier contact stays in the Express-interest area. Keeps the hero uncluttered.

Option B — re-enable the sidebar grid

Would resurface the full quick-facts/assurance/tiers sidebar — heavier, and duplicates the snapshot + tabs.

Option C — leave hidden

Status quo; provenance stays invisible. Rejected.

4.2 SP-2 — spine placement

Option A — between snapshot and tabs Chosen

Story leads, deep detail follows. Reads as one argument without hiding the reference tabs.

Option B — above the snapshot

Pushes the at-a-glance commissioning snapshot down the page.

Option C — as a new lead tab

Keeps the story hidden behind a tab — defeats the narrative-first goal.

4.3 SP-3 — scope

Option A — Luscii only Chosen

Luscii is the test case. Other products get their own records so their conflicts are verified before shipping.

Option B — all four curated narratives now

Would ship unverified device-class/price content for myCOPD/myHeart/Joint Academy. Rejected for this round.
